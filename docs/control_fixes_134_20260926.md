# 時間取樣、重定位銜接與失鎖補位（2026-09-26）

對應本次評估表的第 1、3、4 項。以開始時的未提交工作區為基準；沒有操作硬體。

## 1. 保留遙測事件時間與中間樣本

串流入口改為將已連線的 ARSDK client 傳給 `RtspFrameGrabber`，修正 IP 字串沒有
`.address` 而在影像啟動前拋出例外的整合錯誤。使用假連線及停用的 start 測試
實際建構子契約，未建立網路連線。

ARSDK-NG 分別保存最多 512 筆姿態／速度事件，控制迴圈直接取得完整歷史，
避免 UI 輪詢只保留最新值而遺失中間的加減速與轉向樣本。估計器沿用每筆事件
原始主機 monotonic 收件時間，重複、未來或超過 0.5 秒的取樣不刷新時效。

日誌新增 `control_motion_history`，只記錄尚未寫出的事件，分開保存 yaw 與水平
NED 速度及各自時間戳。離線融合與失鎖重播讀取這些歷史，仍相容既有
`fused_odometry` 場次。新增歷史沒有垂直速度，不能拿來做高度融合。

這修復主機端取樣損失，不等於完成相機曝光與飛機感測器的時鐘校準。
目前 OpenCV RTSP 提供解碼收件時間，ARSDK 提供封包收件時間；兩路網路／解碼
延遲仍須量測。沒有把未知延遲設成估計值或將收件時間改稱曝光時間。

## 3. 重定位修正與到站半徑分離

- 水平 PCMD 的大修正緩升門檻固定為 0.1 地圖單位，與航點半徑無關。
- 弱定位／reseed 確認恢復為強定位，且修正超過 0.02 地圖單位時，控制用水平
  位置在 0.5 秒內混合修正；連續強定位的正常移動不觸發混合。
  最大混合偏移為 0.1 地圖單位。可靠尺度及同時段速度可用時，先扣除正常運動。
- 大於 0.1 地圖單位仍保留既有 1 秒 PCMD 緩升；1.5 地圖單位的跳變暫停不變。
- 重複影格不重啟混合，控制 reset 清除殘留狀態。垂直位置、原始 pose 與其
  時間戳不變；路線進度與降落確認仍先使用原始觀測，再建立控制用位置。

門檻源於目前場域的交接分析，仍以 map unit 表示，不能當成通用公尺設定。

## 4. 正式化失鎖補位離線比較

新增 `tools/replay_outage_bridge.py`，不匯入飛行 SDK。以前 40% 資料估水平尺度
和方向，未收斂或不一致時直接回報無法比較；後 60% 使用不重疊視窗，對照
凍結位置、視覺等速與 NED 速度積分。速度只使用視窗終點之前的資料，遙測缺口
或尾端過期超過 0.5 秒時拒絕該視窗。

輸出 `summary.json` 與 `outages.jsonl`，包含輸入／程式 SHA、校準結果、各失鎖
長度的共同樣本數與 p50/p95/max 殘差。每窗預測明確標為非地圖確認、非到站證據。
參考是保留的視覺位置，不是獨立真值。

正式控制仍維持 0.5 秒、半個到站半徑的短期速度預測。1–5 秒補位只進行離線
比較，沒有啟用長時間橋接或 ESKF。既有實飛原始場次目前已不在審計記錄指向的
位置，因此本次工具驗證使用保存的合成輸入，未宣稱真機精度改善。

```bash
.venv/bin/python tools/replay_outage_bridge.py \
  --session /path/to/recorded_session --out outputs/analysis/outage_bridge
```

其中 `baseline/` 是修改前快照，`own_diff/` 是相對本輪起點的差異，
`full_tests.txt` 為完整離線測試輸出，`wind_matrix_verified/` 保存最終抗風矩陣，
