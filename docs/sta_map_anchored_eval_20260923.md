# 地圖錨定 STA 定位：跨影片離線評估（2026-09-23）

分支 `exp/sta-localization`。只新增離線研究工具，不改 runtime、profile、飛控，
不接硬體。定位路徑完全不使用 EDM、KLT 與 PnP。

## 方法

```text
query 影像 ─ BoQ sideview bank 檢索（排除 query 自己的影片）─ top-5 參考關鍵影格
  每個參考 r：STA(query, r) → T_{q,r}（X_r = R X_q + t）、pose conf、r 的 pointmap
            γ_r = weighted median( z_map / z_STA )，只取 r 自己觀測到的地圖點像素
            C_q = C_r + R_{w,r} · γ_r t，R_{w,q} = R_{w,r} R
  位姿空間共識 → 地圖座標（GlueMap 凍結座標系）的 query 位姿
```

相對先前推導的兩處修改：

1. **γ 的尺度錨點**：不用相鄰關鍵影格的基線比，而用參考影格自己觀測到的
   EDM 重三角化地圖點的相機深度。只比 z，避免 STA 隱含焦距誤差；用加權中位數
   而非 ViSTA Eq. 11 的最小平方，因為地圖點含離群值。ViSTA 原始碼的 scale edge
   本來就只比深度（`estimate_scale_with_depth_and_confidence`）。
2. **共識要獨立**：兩個互相一致的假設必須來自不同影片，或同一影片相隔至少
   72 幀（3 個關鍵影格間距），否則不接受。

## 評估設計

- **Query**：BoQ sideview bank 的 941 張地圖關鍵影格，縮到 1280×720 模擬即時串流
  （`query_camera` 的 K 正好是關鍵影格 K 除以 2.1）。
- **參考**：同一個 bank，但排除 query 所屬影片，所以參考一定來自另一趟飛行。
- **真值**：query 在 GlueMap 模型中的凍結位姿。誤差單位是地圖單位 u。
- **EDM 基準**：正式 provider 的 EDM + lift + PnP，強制使用同一份排名的前 2 名參考
  （`reloc.top_k = 2`），`LOCALIZED_STRONG` 才算接受。
- **已知偏差**：query 自己的觀測參與過地圖點三角化。EDM 的 2D–3D lift 與 STA 的
  γ 都用到這些點，兩者都略為有利；這不是重建層級的留一驗證（vendor
  `official_edm_adapter_loo.py` 也標明同一限制）。
- **不碰保留資料**：只用建圖的 8 支影片，不用 P167/P173/P174。

## 結果

941 個 query、每個 5 組 STA 配對，共 4,705 組；EDM 基準 941 次。上面的參數與
門檻沒有在看到結果後修改。

### 預先登錄的判定：NO-GO

| 項目 | 門檻 | STA 共識 | 通過 |
|---|---|---:|:---:|
| 接受率 | ≥ 50% | 6.4%（60/941） | 否 |
| 位置誤差 p50 | ≤ 0.05 u | 0.058 u | 否 |
| 位置誤差 p95 | ≤ 0.12 u | 0.149 u | 否 |
| 旋轉誤差 p95 | ≤ 5° | 4.1° | 是 |
| 粗大錯誤率（> 0.3 u） | ≤ 1% | 0%（0/60） | 是 |

### 與 EDM + PnP 比較（同一份跨影片排名）

| | 接受 | 位置 p50 | 位置 p95 | 旋轉 p95 | 粗大錯誤 |
|---|---:|---:|---:|---:|---:|
| EDM `LOCALIZED_STRONG`（前 2 名參考） | 580（61.6%） | 0.0063 u | 0.079 u | 1.05° | 0% |
| STA 共識（前 5 名參考） | 60（6.4%） | 0.058 u | 0.149 u | 4.1° | 0% |
| STA top-1（第一個通過 conf 與 γ 檢查的假設） | 195（20.7%） | 0.060 u | 0.153 u | 3.9° | 1.0% |
| STA 全部假設（不設 conf 門檻） | 4,705 | 0.167 u | 0.710 u | 65.9° | 27.3% |

- 兩者都接受的 57 個 query：STA p50 0.059 u，EDM p50 0.0027 u。EDM 受前述
  「query 觀測參與三角化」偏差的程度未量化，這個倍數不能當作即時系統的差距，
  但方向很清楚。
- EDM 失敗的 361 個 query 中，STA 共識只接受 3 個（0.8%，誤差 0.05–0.07 u），
  沒有顯示救援價值。

### 延遲（RTX 5060 Laptop，fp32，GPU 無其他 compute process）

| 階段 | p50 | p95 |
|---|---:|---:|
| STA query 編碼 | 64 ms | 71 ms |
| STA 參考編碼（可離線快取） | 88 ms | 133 ms |
| STA 每組配對解碼 + heads | 49 ms | 72 ms |
| EDM 基準整次（前 2 名，含 match/lift/PnP） | 146 ms | 226 ms |

STA 前 5 名約 64 + 5 × 49 ≈ 310 ms；只用前 2 名約 160 ms。STA 峰值顯存 2.2 GB。

### 事後診斷（不改變上面的判定）

pose conf 有鑑別力，但高信心的配對很少，而且最好的子集仍在 0.06 u 等級：

| pose conf | 假設數 | 位置 p50 | 位置 p95 | 旋轉 p95 |
|---|---:|---:|---:|---:|
| < 0.5 | 3,355 | 0.232 u | 0.828 u | 74.6° |
| 0.5–0.75 | 727 | 0.096 u | 0.348 u | 9.3° |
| 0.75–0.9 | 128 | 0.067 u | 0.239 u | 4.2° |
| ≥ 0.9 | 495 | 0.058 u | 0.146 u | 3.7° |

- 參考影格越近，誤差不會等比例變小：全部假設中參考距離 < 0.1 u 的 377 組，
  位置誤差 p50 仍有 0.126 u（約為參考距離的 2 倍）。STA 平移長度經 γ 換算後與
  真實距離的比值 p50 0.92、p90 2.4，長度本身不穩定。
- 共識被拒的原因：784 個 query 少於兩個有效假設（主要卡在 pose conf < 0.75，
  只有 27% 的配對達標），97 個沒有獨立的互相一致配對。
- 可能原因（未分離驗證）：STA 只用室內資料訓練；輸入 224×224 且只保留中央約
  56% 寬度；空拍場景的基線與深度比很小。

## 結論與後續步驟

- 依預先登錄的門檻，地圖錨定 STA 不能取代 EDM 的定位核心：接受率低一個數量級，
  兩者都接受時誤差約高一個數量級，對 EDM 失敗的幀也幾乎沒有補救。
- 步驟 3（救援片段重播）：目前 `outputs/flight_logs/` 沒有任何實飛錄製的定位
  影格，無法執行。以本結果的 0.8% 補救率，不建議為此安排專門飛行。
- 步驟 4（串接快迴路）：判定為 NO-GO，不進行。
- 若要繼續這個方向，下列都是需要重新預先登錄的新實驗，不能拿本結果調參：
  用場域關鍵影格微調 STA（需以 P173/P174 等保留資料評估，且 8 GB 筆電不一定
  能訓練 0.44B 模型）；或改用有匹配頭、訓練資料含室外場景的模型產生 2D–3D
  對應，保留 PnP。
