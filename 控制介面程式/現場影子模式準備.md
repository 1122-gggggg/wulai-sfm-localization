# 現場影子模式準備

目標是在到達場域前驗證「定位、地圖、航線與影子演算法」所需的所有可離線檢查項目。
這不是飛行核准，也不會解除自主鎖、連線至飛機、起飛或送出 PCMD。

## 出發前

在工作區根目錄執行：

```bash
PYTHONPATH=控制介面程式 .venv/bin/python 控制介面程式/mission_pipeline.py \
  --site-profile 控制介面程式/site_profiles/river_site_edm.json \
  --mode shadow-readiness

.venv/bin/python 定位演算法/flight_control/path_follow_flight.py --selftest
```

第一個指令必須顯示 `package=READY`。它驗證 route、地圖、定位 bundle、參考位姿、
重力對齊檔與 EDM profile 的 SHA-256，並另外列出仍待人員完成的核准項。

`autonomous execution remains LOCKED` 是預期結果，不能用修改 JSON 欄位的方式消除。

## 到場後，可立即進行的零致動驗證

1. 確認只有一個程式持有 Olympe 連線。
2. 使用地面／只讀定位流程確認即時影像、IMU 姿態、視覺 pose 與航線 overlay 都屬於同一個 site profile。
3. 啟動 map-unit shadow estimator；它只輸出 map-units/s、body-axis advisory 與安全建議，不送飛行指令。
4. 記錄至少兩筆連續、品質合格的 visual pose，確認視覺 yaw 增量與 IMU yaw 增量一致。

這些步驟不需要地圖絕對尺度。位置、速度、到達半徑與 route 偏差都以 map units 表示。
但 map yaw 對機體 yaw 的偏移與正負方向仍必須在場域確認；它決定「地圖方向」轉成
body forward/right 時是否正確。

## 只能由實際飛行驗證的項目

下列不是離線、地面或影子模式能證明的項目，必須由現場具權責的人員依核准測試計畫處理：

- 飛行高度、振動、動態模糊與曝光變化下的定位持續性與重定位時間。
- 實機機頭 yaw、相機朝向、map yaw 與 body right 符號的完整一致性。
- 風、不同電量與載荷下，map-unit shadow 建議是否符合實際速度與軌跡趨勢。
- route 的淨空、障礙物、地面效應、起降區與真實可達性。
- 遙控器人工接管、失定位、失串流、GNSS／圍欄、低電量與鏈路中斷時的實際飛機行為。
- 韌體限制、Home／RTH 設定、遙測頻率與硬體／韌體版本是否與核准 receipt 一致。

只有完成場域風險審查、航線淨空、人員／硬體核准及人工飛行測試後，才能由負責人決定是否進入下一階段。此文件不構成飛行授權。
