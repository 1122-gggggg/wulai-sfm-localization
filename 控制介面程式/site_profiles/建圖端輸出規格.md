# 建圖端輸出規格

控制介面的「① 場域建圖資料夾」一次只接受一個完整資料夾。固定入口檔名是
`site_profile.json`；其餘檔名可以不同，但必須由這份 manifest 使用相對路徑明確
指定。控制介面不會依副檔名猜檔案，也不會把不同場域的檔案拼在一起。

## 建圖端必須輸出的五個檔案（`direct` 後端）

```text
場域資料夾/
├── site_profile.json                          # 場域 manifest、相機、座標系、SHA-256
├── map/map.ply                                # UI 顯示用 RGB 點雲
├── localization/direct_bundle.json            # 已完成的 direct 定位 bundle manifest
├── localization/direct_localizer_profile.json # direct reloc / tracker / PnP 參數
└── localization/reference_poses.json          # bundle 內每張參考影像的 SfM 位姿
```

這五項都是目前匯入接口的必需項。匯入器會完整讀取並驗證後才把整組資料原子化
放到 `地圖檔/場域/<site_id>/`。若同一 `site_id` 已存在但內容不同，會拒絕覆寫。

### 1. `site_profile.json`

必須使用 `schema_version: 2`，並至少包含：

- 唯一且可作為資料夾名稱的 `site_id`，以及給人看的 `display_name`。
- `localizer: "direct"`。
- `localizer_deploy_dir`：指向 `定位演算法/deploy_code/sfm_direct_deploy`；不要把
  runtime 程式複製進場域包。
- 四個資產相對路徑：`assets.map_ply`、`assets.localization_bundle`、
  `localizer_profile`、`map_reference_poses`。
- `query_camera`：實際送進定位器之影像的 model、width、height、params。
- `coordinate_frame`：這次重建的唯一 ID 與固定 GLOMAP 軸向宣告。
- `asset_sha256`：PLY、bundle manifest、runtime profile、reference poses 四個檔案的
  64 字元 SHA-256。

最小結構如下。SHA-256 必須由建圖端依實際檔案計算，不可照抄範例：

```json
{
  "schema_version": 2,
  "site_id": "new-site",
  "display_name": "New Site",
  "localizer": "direct",
  "localizer_deploy_dir": "../../../../../定位演算法/deploy_code/sfm_direct_deploy",
  "localizer_profile": "localization/direct_localizer_profile.json",
  "map_reference_poses": "localization/reference_poses.json",
  "query_camera": {
    "model": "PINHOLE",
    "width": 1280,
    "height": 720,
    "params": [960.4853099760471, 958.1961747147875, 670.8167651412149, 358.7191813450141]
  },
  "coordinate_frame": {
    "id": "new-site-reconstruction-v1",
    "convention": "glomap",
    "horizontal_axes": ["x", "z"],
    "up_axis": "-y",
    "handedness": "right",
    "units": "map"
  },
  "asset_sha256": {
    "map_ply": "<map/map.ply 的 SHA-256>",
    "localization_bundle": "<localization/direct_bundle.json 的 SHA-256>",
    "localizer_profile": "<localization/direct_localizer_profile.json 的 SHA-256>",
    "map_reference_poses": "<localization/reference_poses.json 的 SHA-256>"
  },
  "assets": {
    "map_ply": "map/map.ply",
    "route_json": null,
    "localization_bundle": "localization/direct_bundle.json",
    "megaloc_cache": null,
    "track_landmarks": null,
    "poles_json": null
  }
}
```

`query_camera` 不是「拍建圖照片的任一台相機」；它必須對應飛行時送入定位器的
1280×720 畫面及同一個縮放／裁切流程。匯入器會要求它與
`localization/reference_poses.json` 的 `camera` 完全一致。

### 2. `map/map.ply`

- 支援 PLY 1.0 ASCII 或 binary little-endian。
- 至少一個 vertex。
- 每個 vertex 必須有 `x y z red green blue`；RGB 是目前 UI 顯示器所需。
- 座標必須與 direct bundle 與 reference poses 來自同一次重建。

PLY 只儲存 XYZ 數值，不會自行說明哪個軸是高度。軸向不需要另外匯入一份檔案，
但建圖端必須把它寫在 `site_profile.json.coordinate_frame`。目前接口只接受原始
GLOMAP 約定：X/Z 為水平面、-Y 為上、右手座標、單位為 `map`。控制介面不會
從 PLY 猜軸向，也不會假設 map unit 等於公尺。

### 3. `localization/direct_bundle.json`（schema `direct-localization-bundle/v1`）

`direct` 是 two-rate 定位後端（CPU KLT 快迴路 + 背景 GPU MegaLoc/EDM reloc）。
它的地圖不是打包好的單一權重檔，而是一份 COLMAP model + 磁碟上的 keyframe JPEG +
MegaLoc descriptor bank，由這份 JSON manifest 把它們綁在一起。

所有路徑都相對於**這個檔案自己所在的目錄**。

| 欄位 | 型別 | 意義 |
|---|---|---|
| `schema` | str | 固定 `"direct-localization-bundle/v1"` |
| `map_revision_id` | str | 地圖版本 ID，與 release 目錄名一致 |
| `coordinate_frame_id` | str | `<map_revision_id>_<model_sha12>`；必須等於 `site_profile.coordinate_frame.id` |
| `model_dir` | path | COLMAP model 目錄（`cameras/images/points3D/rigs/frames.bin`） |
| `keyframes_manifest` | path | `keyframes.jsonl`，每列帶 `output_name` 與 `image_sha256` |
| `keyframes_images_root` | path | keyframe JPEG 根目錄 |
| `reference_manifest` | path | reloc 用的參考影像清單（JSONL） |
| `reference_bank` | object | `{name, descriptors, names}`；本 release 是 `sideview` + `megaloc_references_sideview.npy` + `.names.json` |
| `intersection_cells` | path \| null | FIM/LWTL 交集 cell 檔 |
| `reference_depth_dir` | path \| null | MoGe3 depth 目錄（reloc 的 hedge lift 用） |
| `model_sha256` | object | model 目錄下每個 `.bin` 的 SHA-256 |
| `files` | array | 每筆 `{path, sha256, size_bytes}` |

`files[]` 必須涵蓋：model 的每個 `.bin`、`reference_manifest`、兩個 bank 檔、
`intersection_cells`、`keyframes.jsonl`。**不含** keyframe JPEG 與 depth `.npz`——
它們的 SHA-256 已經在 `keyframes.jsonl` 的 `image_sha256` 欄位，由 runtime 在第一次
載入該張參考圖時逐張驗證。本 release 的 `files[]` 共 10 筆（來源：
`地圖檔/場域/river_site/releases/river_gluemap_all8_direct_20260908/localization/direct_bundle.json`）。

`site_profile.asset_sha256.localization_bundle` 是 **`direct_bundle.json` 本身**的
SHA-256，不是 model 或 bank 的雜湊。

### 4. `localization/direct_localizer_profile.json`（schema `direct-deployment-profile/v1`）

必須是 `schema: "direct-deployment-profile/v1"`。這份檔案就是凍結組態，
**生產路徑不讀任何環境變數旋鈕**。頂層五個區塊：

| 區塊 | 必要欄位 |
|---|---|
| 頂層 | `schema`、`name`、`map_scale`、`intrinsics` |
| `intrinsics` | `schema_version`、`image_width`、`image_height`、`K`（3×3）、`images_are_undistorted` |
| `reloc` | `top_k`、`lift_distance_px`、`period_s`、`min_points`、`reference_bank`、`min_reference_occupied_bins`、`bank_occupancy_percentile`、`descriptor_batch_size`、`batch_refs`、`reference_cache_size`、`frozen_pnp_thresholds` |
| `reloc.frozen_pnp_thresholds` | `strong_inliers`、`minimum_inlier_ratio`、`minimum_hull_coverage`、`minimum_occupancy_4x4`、`minimum_positive_depth_ratio`、`maximum_reprojection_p90_px` |
| `fast_loop` | `resolution`、`tracker`、`track_cap`、`reseed_min_points`、`topup`、`klt{fb_max_px,win,levels}`、`pnp{max_error_px,min_trials,max_trials,confidence,refine_iters,min_points,min_inliers}` |
| `vo` | `enabled`、`keyframe_stride`、`batch_lag`、`min_live`、`detect_cap`、`min_distance`、`min_parallax_deg`、`max_reproj_px`、`refine`、`window_ba` |
| `dead_reckon` | `enabled`、`max_frames` |

本 release 的凍結值（來源：`.../localization/direct_localizer_profile.json`）：
`reloc.top_k = 2`（:29）、`reloc.period_s = 0.3`（:31）、
`reloc.reference_bank = "sideview"`（:33）、`reference_cache_size = 1024`（:38）、
`strong_inliers = 80`（:40）、`minimum_inlier_ratio = 0.25`（:41）、
`maximum_reprojection_p90_px = 3.0`（:45）、`fast_loop.resolution = [960, 540]`（:49-52）、
`track_cap = 500`（:54）、`pnp.max_error_px = 4.0`（:63）、`pnp.confidence = 0.999`（:66）、
`vo.keyframe_stride = 8`（:74）、`vo.batch_lag = 6`（:75）、`vo.min_live = 350`（:76）、
`vo.window_ba = false`（:82）、`dead_reckon.max_frames = 300`（:86）。
這一組對應 `river-deploy-5060-20260908/P174_AND_NEXT.md:58-65` 的凍結 env。

`fast_loop.resolution` 是**快迴路內部**的縮放尺寸；`site_profile.query_camera` 仍
宣告 1280×720 的真實串流相機。縮放只發生在 tracker 內部，內參依實際傳入影像尺寸
換算。匯入器會用目前 production profile loader 驗證，缺少欄位或多出未知欄位都會拒絕。

### 5. `localization/reference_poses.json`

必須包含：

```json
{
  "camera": {
    "model": "PINHOLE",
    "width": 1280,
    "height": 720,
    "params": [960.4853099760471, 958.1961747147875, 670.8167651412149, 358.7191813450141]
  },
  "poses": {
    "reference-image-name.jpg": {
      "R": [[1, 0, 0], [0, 1, 0], [0, 0, 1]],
      "t": [0, 0, 0]
    }
  }
}
```

`poses` 的 key 集合必須與 bundle 的參考影像集合完全相同；每個 R 是有限的 3×3
矩陣、t 是有限的三元素向量。它用來對齊／過濾 UI 點雲並檢查建圖資產沒有混場。

### `direct` 場域包的其他必要內容

`direct_bundle.json` 用相對路徑指出去的檔案都必須跟著進 release：

```text
model/{cameras,images,points3D,rigs,frames}.bin、model/occupancy.json
keyframes/keyframes.jsonl、keyframes/images/<video_id>/*.jpg
depth_moge3/<video_id>/*.npz
localization/{reference_manifest.jsonl,megaloc_references_sideview.npy,
              megaloc_references_sideview.names.json,
              fim_lwtl_intersection_cells.json,T_align_gravity.json}
```

`site_profile.localizer_deploy_dir` 必須指向
`定位演算法/deploy_code/sfm_direct_deploy`；不要把 runtime 程式複製進場域包。
新座標系、沒有航線、沒有現場驗收的 release，`flight.approved` 必須是 `false`。

## 另外兩個獨立接口

這兩項不要放進必需的建圖包流程。先匯入場域，再依任務需要分別匯入：

### 預畫航線 JSON

```json
{
  "schema": "sfm-flight-route/v1",
  "site_id": "new-site",
  "coordinate_frame_id": "new-site-reconstruction-v1",
  "frame": "glomap",
  "units": "map",
  "purpose": "flight",
  "closed": false,
  "waypoints": [[0, 0, 0], [1, 0, 0]]
}
```

`frame` 可為 `glomap` 或 `aligned`，至少兩個 waypoint 且必須有非零線段。匯入
航線只提供 overlay／未來路徑控制資料，仍會把飛行核准維持為關閉。

### 電桿／目標物 JSON

```json
{
  "schema": "sfm-inspection-targets/v1",
  "site_id": "new-site",
  "coordinate_frame_id": "new-site-reconstruction-v1",
  "frame": "aligned",
  "units": "map",
  "poles": [
    {"base": [0, 0, 0], "top": [0, 0, 2]}
  ]
}
```

目前巡檢控制器的目標物接口固定接受 `aligned` 座標。每個 pole 可提供
`base` + `top`，或直接提供 `center`。這份檔案只有巡檢任務需要。

## 不必從建圖端輸出的項目

- PLY 軸向的額外檔案：不需要，語意寫在 `site_profile.json`。
- reference image 資料夾：不需要，keyframe JPEG 已由 `keyframes.jsonl` 逐張 SHA-256 綁定。
- VPR descriptor cache：不需要，global descriptors 已在 release 的 MegaLoc bank（`.npy` + `.names.json`）。
- 飛行用 landmark sidecar：正式 direct 場域不需要。
- 航線與目標物：不是基本定位包必需，使用各自的 UI 接口。
- 飛行核准與硬體 approval receipt：不能由建圖完成自動產生；必須另行完成現場
  路線淨空與真機版本測試。匯入器永遠先以未核准狀態建立場域。
