# 建圖端輸出規格

控制介面的「① 場域建圖資料夾」一次只接受一個完整資料夾。固定入口檔名是
`site_profile.json`；其餘檔名可以不同，但必須由這份 manifest 使用相對路徑明確
指定。控制介面不會依副檔名猜檔案，也不會把不同場域的檔案拼在一起。

## 建圖端必須輸出的五個檔案

```text
場域資料夾/
├── site_profile.json             # 場域 manifest、相機、座標系、SHA-256
├── map.ply                       # UI 顯示用 RGB 點雲
├── localization_bundle.pt        # 已完成的 EDM 定位 bundle
├── edm_runtime_profile.json      # EDM matcher / tracker 參數
└── reference_poses.json          # bundle 內每張參考影像的 SfM 位姿
```

這五項都是目前匯入接口的必需項。匯入器會完整讀取並驗證後才把整組資料原子化
放到 `地圖檔/場域/<site_id>/`。若同一 `site_id` 已存在但內容不同，會拒絕覆寫。

### 1. `site_profile.json`

必須使用 `schema_version: 2`，並至少包含：

- 唯一且可作為資料夾名稱的 `site_id`，以及給人看的 `display_name`。
- `localizer: "edm"`。
- 四個資產相對路徑：`assets.map_ply`、`assets.localization_bundle`、
  `localizer_profile`、`map_reference_poses`。
- `query_camera`：實際送進定位器之影像的 model、width、height、params。
- `coordinate_frame`：這次重建的唯一 ID 與固定 GLOMAP 軸向宣告。
- `asset_sha256`：PLY、bundle、runtime profile、reference poses 四個檔案的
  64 字元 SHA-256。

最小結構如下。SHA-256 必須由建圖端依實際檔案計算，不可照抄範例：

```json
{
  "schema_version": 2,
  "site_id": "new-site",
  "display_name": "New Site",
  "localizer": "edm",
  "localizer_profile": "edm_runtime_profile.json",
  "map_reference_poses": "reference_poses.json",
  "query_camera": {
    "model": "SIMPLE_RADIAL",
    "width": 1280,
    "height": 720,
    "params": [934.139423, 640.0, 360.0, 0.001061]
  },
  "coordinate_frame": {
    "id": "new-site-reconstruction-v1",
    "convention": "glomap",
    "horizontal_axes": ["x", "z"],
    "up_axis": "-y",
    "handedness": "right",
    "units": "map"
  },
  "asset_sha256": {
    "map_ply": "<map.ply 的 SHA-256>",
    "localization_bundle": "<localization_bundle.pt 的 SHA-256>",
    "localizer_profile": "<edm_runtime_profile.json 的 SHA-256>",
    "map_reference_poses": "<reference_poses.json 的 SHA-256>"
  },
  "assets": {
    "map_ply": "map.ply",
    "route_json": null,
    "localization_bundle": "localization_bundle.pt",
    "megaloc_cache": null,
    "track_landmarks": null,
    "poles_json": null
  }
}
```

`query_camera` 不是「拍建圖照片的任一台相機」；它必須對應飛行時送入 EDM 的
1280×720 畫面及同一個縮放／裁切流程。匯入器會要求它與
`reference_poses.json.camera` 完全一致。

### 2. `map.ply`

- 支援 PLY 1.0 ASCII 或 binary little-endian。
- 至少一個 vertex。
- 每個 vertex 必須有 `x y z red green blue`；RGB 是目前 UI 顯示器所需。
- 座標必須與 EDM bundle 與 reference poses 來自同一次重建。

PLY 只儲存 XYZ 數值，不會自行說明哪個軸是高度。軸向不需要另外匯入一份檔案，
但建圖端必須把它寫在 `site_profile.json.coordinate_frame`。目前接口只接受原始
GLOMAP 約定：X/Z 為水平面、-Y 為上、右手座標、單位為 `map`。控制介面不會
從 PLY 猜軸向，也不會假設 map unit 等於公尺。

### 3. `localization_bundle.pt`

必須是已建置完成、可直接給飛行端載入的 EDM relocation bundle。根物件至少有：

- `meta`：`feature=edm`，grid 128×72，input 1024×576。
- `ref_names`：唯一且非空的參考影像名稱。
- `ref_global`：每張參考影像的有限 MegaLoc descriptor。
- `refs`：key 必須與 `ref_names` 完全相同。每個 entry 恰含
  `xyz_by_cell`（9216×3 float32）與 `image_jpg`（非空 uint8）。

可另外包含 `ref_centers`、`ref_yaws`、`covis`。參考影像 JPEG 已嵌在 bundle，
所以飛行端不需要再匯入 reference image 資料夾。不要把 COLMAP／GLOMAP 原始
database、稀疏模型或尚待轉換的 checkpoint 當成此 `.pt`。

### 4. `edm_runtime_profile.json`

必須是 `schema: "edm-deployment-profile/v1"`，並具有完整的 `matcher` 與
`tracker` 欄位。`matcher.input_size` 固定為 `[1024, 576]`。建圖端可以複製經驗證
的共用預設，再針對場域調整；匯入器會用目前 production profile loader 驗證，
缺少欄位或多出未知欄位都會拒絕。

### 5. `reference_poses.json`

必須包含：

```json
{
  "camera": {
    "model": "SIMPLE_RADIAL",
    "width": 1280,
    "height": 720,
    "params": [934.139423, 640.0, 360.0, 0.001061]
  },
  "poses": {
    "reference-image-name.jpg": {
      "R": [[1, 0, 0], [0, 1, 0], [0, 0, 1]],
      "t": [0, 0, 0]
    }
  }
}
```

`poses` 的 key 集合必須與 bundle 的 `ref_names` 完全相同；每個 R 是有限的 3×3
矩陣、t 是有限的三元素向量。它用來對齊／過濾 UI 點雲並檢查建圖資產沒有混場。

## 另外兩個獨立接口

這兩項不要放進必需的建圖包流程。先匯入場域，再依任務需要分別匯入：

### 預畫航線 JSON

```json
{
  "schema": "sfm-flight-route/v1",
  "site_id": "new-site",
  "coordinate_frame_id": "new-site-reconstruction-v1",
  "frame": "glomap",
  "units": "map",
  "purpose": "flight",
  "closed": false,
  "waypoints": [[0, 0, 0], [1, 0, 0]]
}
```

`frame` 可為 `glomap` 或 `aligned`，至少兩個 waypoint 且必須有非零線段。匯入
航線只提供 overlay／未來路徑控制資料，仍會把飛行核准維持為關閉。

### 電桿／目標物 JSON

```json
{
  "schema": "sfm-inspection-targets/v1",
  "site_id": "new-site",
  "coordinate_frame_id": "new-site-reconstruction-v1",
  "frame": "aligned",
  "units": "map",
  "poles": [
    {"base": [0, 0, 0], "top": [0, 0, 2]}
  ]
}
```

目前巡檢控制器的目標物接口固定接受 `aligned` 座標。每個 pole 可提供
`base` + `top`，或直接提供 `center`。這份檔案只有巡檢任務需要。

## 不必從建圖端輸出的項目

- PLY 軸向的額外檔案：不需要，語意寫在 `site_profile.json`。
- reference image 資料夾：不需要，影像已嵌入 EDM bundle。
- MegaLoc cache：不需要，global descriptors 已在 bundle 的 `ref_global`。
- XFeat track landmarks：正式 EDM 場域不需要。
- 航線與目標物：不是基本定位包必需，使用各自的 UI 接口。
- 飛行核准與硬體 approval receipt：不能由建圖完成自動產生；必須另行完成現場
  路線淨空與真機版本測試。匯入器永遠先以未核准狀態建立場域。
